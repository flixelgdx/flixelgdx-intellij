Reports reflection, which breaks on the web and on Android with R8.

Reflection means looking up classes, methods or fields by name while the game runs, for example Class.forName("Enemy") or getDeclaredMethod("update"). It works on a desktop JVM, but some platforms compile the game ahead of time and remove, rename or never see the things reflection looks for: the web build (TeaVM) has no reflection at all, and Android's R8 shrinker renames and deletes code it thinks is unused. The result is a crash that only happens on the device or in the browser, which is hard to debug.

This inspection reports java.lang.reflect, the lookup methods of Class (forName, getDeclaredMethod(s), getDeclaredField(s), getDeclaredConstructor(s), getMethod(s), newInstance and similar), proxies, MethodHandles.Lookup.find* and Kotlin's kotlin.reflect.full.

Write the code explicitly instead, or let the framework's annotation processors generate it at build time.

Before:

Enemy enemy = (Enemy) Class.forName("game.Enemy").getDeclaredConstructor().newInstance();

After:

Enemy enemy = new Enemy();

Suppress with @SuppressWarnings("FlixelGdxReflection") (Java) or @Suppress("FlixelGdxReflection") (Kotlin), for code that only runs on the desktop.
