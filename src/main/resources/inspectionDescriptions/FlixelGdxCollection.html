Reports standard Java collections (ArrayList, HashMap, HashSet and friends) in a FlixelGDX game.

Java's collections were built for general programs, not for games. Every for-each loop over them creates an iterator object, every int or float you store is wrapped in an object (boxing), and they keep extra bookkeeping per entry. In a game those small costs add up to a steady stream of garbage, and garbage collection pauses make the game stutter.

FlixelGDX has its own collections in org.flixelgdx.collections that allocate nothing while a game runs, and iterating over them is safe to do every frame. This inspection reports the java.util collection types in fields, local variables, parameters and new expressions, and the Kotlin helpers such as mutableListOf and hashMapOf. Parameters of overriding methods are skipped, because their type is decided by the method they override.

The closest FlixelGDX collection is:

  • List or ArrayList: FlixelArray<T>, or a primitive array such as FlixelIntArray or FlixelFloatArray when the elements are boxed numbers
  • Set or HashSet: FlixelSet<T>, FlixelIntSet for Integer, FlixelLongSet for Long
  • Map or HashMap: FlixelMap<K, V>; FlixelIntMap<V> and FlixelLongMap<V> for Integer and Long keys; FlixelObjectIntMap<K> and FlixelObjectFloatMap<K> for number values
  • IdentityHashMap: FlixelIdentityMap<K, V>

For a field or local variable that is created with a no-argument or a capacity constructor, the quick fix Replace with ... rewrites the declaration. It does not rewrite the calls, because the method names differ (for example getSize() instead of size()), so the IDE will show errors on those lines until you update them. Ordered and sorted collections (LinkedHashMap, TreeMap, LinkedList and so on) have no exact equivalent, so they are only reported.

Before:

private final Map<Integer, Enemy> enemies = new HashMap<>();

After:

private final FlixelIntMap<Enemy> enemies = new FlixelIntMap<>();

Suppress with @SuppressWarnings("FlixelGdxCollection") (Java) or @Suppress("FlixelGdxCollection") (Kotlin).
