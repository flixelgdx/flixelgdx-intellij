Reports library APIs that are missing on Android or the web.

A FlixelGDX game runs on the desktop, on Android and in the browser, but the three do not share one Java library. Android's runtime only has the Java 17 library, and the web build only has the classes TeaVM provides. A call that compiles fine on a new desktop JDK can therefore crash the game on a phone or in a browser, and you only find out when you run it there.

The inspection reports: java.lang.foreign, ScopedValue, StructuredTaskScope, virtual threads (Thread.ofVirtual, Thread.startVirtualThread, Executors.newVirtualThreadPerTaskExecutor), java.lang.classfile, the Java 21 sequenced collection methods (getFirst, getLast, reversed, addFirst, addLast, removeFirst, removeLast on lists and sets), Math.clamp, StringBuilder.repeat, HexFormat, Thread.threadId and Locale.of. The message names a replacement when there is one.

Before:

float x = Math.clamp(value, 0f, 1f);
Item last = items.getLast();

After:

float x = FlixelMath.clamp(value, 0f, 1f);
Item last = items.get(items.size() - 1);

If a module never runs on Android or the web, suppress the warning with @SuppressWarnings("FlixelGdxUnsupportedApi") (Java) or @Suppress("FlixelGdxUnsupportedApi") (Kotlin).
