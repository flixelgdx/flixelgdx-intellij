Reports code that creates new objects inside the per-frame methods of a FlixelGDX game.

A game redraws many times a second. The methods that run every frame (the ones that override update(float) or draw(...)) are called so often that anything created inside them becomes garbage almost immediately. When the garbage collector cleans up, the game pauses for a moment, and that shows up as a stutter, most of all on phones and in the browser.

This inspection reports, inside those methods: new objects, arrays, text built with +, numbers boxed into a collection (for example list.add(5) on a list of Integer), and lambdas or anonymous classes that use variables from the surrounding code. Constants, enum values and string literals are fine, and code inside throw is ignored. A Kotlin lambda passed to a standard library function such as forEach is ignored as well, because the compiler usually inlines it.

The fix is to create the object once and reuse it. For a local variable whose initializer does not depend on anything in the method, Java files get the quick fix Move to a field.

Before:

public void update(float elapsed) {
  super.update(elapsed);
  Vector2 offset = new Vector2(4, 4);
  follow(offset);
}

After:

private Vector2 offset = new Vector2(4, 4);

public void update(float elapsed) {
  super.update(elapsed);
  follow(offset);
}

The object is now shared by every frame, so do not keep a reference to it after the method returns. To silence the warning on purpose, use @SuppressWarnings("FlixelGdxAllocation") (Java) or @Suppress("FlixelGdxAllocation") (Kotlin).
